# Production-чеклист

## Переменные окружения

Скопируйте значения из `.env.example` в секреты хостинга. Укажите реальный HTTPS-домен без завершающего `/`, длинный случайный `AUTH_SECRET`, созданный через `npm run admin:hash` хеш пароля и строку подключения PostgreSQL.

После создания каталога резервных копий выполните на сервере:

```bash
npm run deploy:check
```

Команда проверяет HTTPS-адреса, секреты, доступность PostgreSQL и возможность записи в `BACKUP_DIR`. Она не выводит значения секретов.

## HTTPS

Включите SSL-сертификат и перенаправление HTTP на HTTPS в панели хостинга или reverse proxy. Заголовок HSTS уже добавляет приложение; включать его следует только после успешной проверки HTTPS на домене.

## Резервные копии

На сервере должен быть установлен совместимый `pg_dump`. Проверка ручного запуска:

```bash
npm run db:backup
```

Добавьте эту команду в планировщик хостинга или cron минимум раз в сутки. Ограничьте доступ к `BACKUP_DIR`, храните копии отдельно от приложения, настройте срок хранения и регулярно проверяйте восстановление через `pg_restore`. Если резервные копии выполняет провайдер PostgreSQL, включите ежедневный график и point-in-time recovery, а `DATABASE_BACKUPS_ENABLED=true` установите только после проверки политики хранения.

## Релиз

Перед переключением домена выполните `npm run deploy:check`, затем `npm run deploy:build`. После запуска проверьте `/`, несуществующий адрес, `/admin`, `/robots.txt`, `/sitemap.xml` и резервную копию.
